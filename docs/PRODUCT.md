## Project Pocket と PocketPad

この2つは競合しない。**層が違う。**

```
┌─────────────────────────────────────────┐
│ PocketPad / かんぱにっち                 │  ← ユーザーが触れる体験
│   日々の小さな行動を、世界と図鑑に変える  │     「人生を育てるアプリ」
├─────────────────────────────────────────┤
│ Project Pocket                          │  ← それを成立させる基盤
│   人・AI・端末・プロジェクトをつなぐ      │     内部の構想
│   Core / Companion / Input / Hub / …     │
└─────────────────────────────────────────┘
```

- **PocketPad** は基盤の上で動く**最初の主力プロダクト**。Companionモジュールの一機能ではない
- **Project Pocket** を表向きの製品コンセプトにしない。抽象的すぎて誰にも刺さらない。
  ユーザーに見せるのは PocketPad、Project Pocket は**内部のプラットフォーム構想**として扱う
- **PCリモコンは基盤の入力・接続機能**。原点ではあるが、もう証明済みの能力であって売りではない

正式な表示名（Project Pocket / PocketPad / Pocket Companion …）は今後変えられるようにし、
**コードや内部構造を名称へ強く依存させない。**

## 解決する問題

- PCの前にいないと作業を進めにくい
- AIとの会話と実際の開発環境が分離している
- アイデアを設計書にするのが難しい
- 初心者はAIへ何を指示すればよいか分からない
- 複数のAI・ツール・プロジェクトがバラバラに存在している
- **過去に決めた思想や仕様を忘れやすい**
- スマホからPCを操作する既存アプリは、開発作業に最適化されていない
- **AIに任せすぎると、人の目的や思想が薄くなる**

そして作者自身の問題——**ADHDで、記憶を外に置いておく道具が要る。**
だから一覧は「全部ここにある」ことを裏切ってはいけないし、表示が嘘をつくのが一番まずい。

## MVP

> **日々の行動が世界を変え、図鑑になる体験を、人が続けて愛せるか。**

これを証明する。

```
① タスク追加 → ② AIが解析 → ③ 世界が変化 → ④ 図鑑追加 → ⑤ ホーム更新
```

### なぜ「開発AIの操作」をMVPにしないか

「スマホからPC上の開発AIを操作できる」は**すでに実装によって証明されている**。
トラックパッド・キーボード・マクロ・音声入力・ショートカットは動いていて、
Claude Codeのフックも繋がっている。

これはMVPではなく**成立済みの基盤能力**。ここを前面に出すと、PocketPadは
「便利な開発者向けリモコン」として理解され、VISIONの独自性が埋もれる。

**次に検証すべき最大の不確実性は③**——行動が世界になる体験が、続くかどうか。

### MVPで作らないもの

SNS / 大規模コミュニティ / 複数AIエージェントの自動協調 / クラウド必須構成 /
高度なファイル管理 / 独自AIモデル / 完全な遠隔デスクトップ / 複雑な課金 / 多数の設定画面

## 現在地

MVPの5段のうち、**残っている本体は③だけ**。

| MVP段 | 状態 |
|---|---|
| ① タスク追加 | **済** — Claude Codeのフック／スマホから手動追加 |
| ② AIが解析 | **済** — ルールで拾い、決まらないものだけAIへ |
| ③ 世界が変化 | **これから。** 部屋がまだ固定 |
| ④ 図鑑追加 | **キャラぶんは済** — 日替わりキャラと過去の図鑑 |
| ⑤ ホーム更新 | **済** — WebSocketで即時 |

「AIが毎日行動を見て世界を少し変える」パイプラインは、**キャラ1体ぶんだけ完成している**。
③はその一般化であって、ゼロからではない（→ [ARCHITECTURE.md](ARCHITECTURE.md)）。

## モジュール

Project Pocket の内部区分。**空の構造を先に作らず、必要になった部分から足す。**

| # | モジュール | 中身 | 現状 |
|---|---|---|---|
| 1 | **Core** | ユーザー設定 / プロジェクト管理 / 会話履歴 / 権限 / 接続 / モジュール管理 | 一部 |
| 2 | **Companion** | AI相棒との会話 / 音声 / ユーザー理解 / プロジェクト記憶 / 提案 | 実況・キャラが該当 |
| 3 | **Input Device** | トラックパッド / キーボード / 音声 / ショートカット / マクロ | **完成** |
| 4 | **Team Skills** | 設計 / 実装 / デザイン / 調査 / レビュー / ドキュメント | 未 |
| 5 | **Project Hub** | 一覧 / コア思想 / 仕様 / ロードマップ / タスク / GitHub / Markdown | タスクのみ |
| 6 | **Social Connection** | 仲間 / チーム / コミュニティ / 共同プロジェクト / 招待 / 権限 | 未 |
| 7 | **Streaming** | OBS操作 / コメント / 台本 / 字幕 / 相棒表示 | 未 |
| 8 | **Open Source Infra** | GitHub連携 / Issue / PR / Markdown / モジュール追加 / フォーク | 一部 |
| 9 | **Personal Server** | 自宅PC / N100 / Mac mini / VPS / Tunnel / 分散 | 一部 |
| 10 | **UI / Gadget Layer** | Android / iPhone / Windows / Web / BT / USB / Wi-Fi | Android のみ |

**Team Skills はユーザーに複雑なエージェント構成を見せない。**
必要なときに「チームを呼ぶ」という分かりやすい体験にする。

**Social Connection で AI は人間関係の代わりにならない。** 人同士をつなぐ支援だけをする。

## 013〜016の位置づけ

**独立した別アプリとして分断しない。** Project Pocket の中で動くフェーズ／モジュール／
実験／スキル／接続先として統合できる設計を基本とする。

| 号機 | 中身 | 統合の形 |
|---|---|---|
| **013** | PocketPad / かんぱにっち | 基盤そのもの＋最初の主力プロダクト |
| **015** | PROJECT GODDESS（ブラウザ間チャット） | Social Connection の実験 |
| **016** | BEAT TAG（リズムゲーム） | かんぱにっちから起動できるガジェット |
| **011** | RoadTalk（送迎・配車） | 別ドメインの実験 |
| **002** | 家計Bot（レシート→家計簿） | 生活側の入力経路として資産を流用 |

繋ぎ方は共通ランチャー構想（`gadget.json` にマニフェストを置く）で扱う。

## ロードマップ

| Phase | 名前 | 中身 | 現在地 |
|---|---|---|---|
| 1 | **Pocket Input** | トラックパッド / キーボード / 音声 / ショートカット / 自動接続 | ✅ **完成** |
| 2 | **Pocket Developer** | Codex・Claude Code操作 / プロンプト履歴 / 実行状態 / 承認 | 🔸 フックで実況まで |
| 3 | **Pocket Project** | プロジェクト一覧 / 設計思想 / Markdown / タスク / GitHub / 要約 | 🔸 タスクと日誌 |
| 4 | **Pocket Companion** | 音声会話 / プロジェクト記憶 / 設計支援 / 指示書作成 / レビュー | 🔸 キャラと実況 |
| 5 | **Pocket Team** | PM / 設計 / 実装 / デザイン / 調査 / テスト / レビュー | ⬜ |
| 6 | **Pocket Community** | 人と人、プロジェクト同士をつなぐ | ⬜ |

**順番どおりには進んでいない。** Phase 1 が完成した後、
かんぱにっちが Phase 3〜4 の領域へ先に飛んでいる。
それでいい——ロードマップは順路ではなく地図として使う。
